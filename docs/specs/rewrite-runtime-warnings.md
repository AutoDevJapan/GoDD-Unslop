# 改稿時に読み込めなかった指示を知らせる

CodexがSkill一覧や上位の指示ファイルを省略しても、改稿本文が返れば、これまではその注意点を利用者に伝えていませんでした。
改稿の成功と、読み込めた指示の範囲は分けて確認できるようにします。

## 返す内容

成功した`rewrite`・`rewrite-for`・MCPの`unslop_rewrite`は、既存の結果に`runtime_warnings`を追加します。
各要素は固定の`id`と日本語の`message`です。該当しなければ空の配列を返します。

| id | 知らせること |
| --- | --- |
| `skills_context_budget` | 初期のSkill一覧が省略されたため、自動選択に影響する可能性がある |
| `skills_scan_limit` | Skillの走査が上限に達し、一部を見つけられていない可能性がある |
| `project_instructions_truncated` | 上位・プロジェクトの指示ファイルが一部省略された |

識別子は警告の種類を表し、どのSkillやどのファイルが欠けたかを断定しません。
同じ種類は、複数の出力で見つかっても1件にまとめます。

標準出力のJSONLは、`item.completed`の`item.type=error`にある既知の警告だけを調べます。
標準エラーは、既知の走査上限・指示の切り詰めの診断だけを分類します。
自由文、パス、認証値、未知のエラー本文は結果へコピーしません。
生成本文に警告と同じ言葉があっても、実行環境の警告として扱いません。

## 利用者の受入条件

- Given: 既知の省略警告と改稿本文を返す接続先。When: CLIまたはMCPから改稿する。Then: 成功本文と既存の比較結果を保ち、`runtime_warnings`も実際の返却JSONに入る。
- Given: 同じ警告を繰り返す接続先。Then: 同じidは1件だけ返る。
- Given: 無警告、未知の診断、警告文を含む生成本文。Then: 未知の内容を警告へ転送せず、該当警告は空になる。
- Given: パスや秘密に見立てた文字列を含む診断。Then: 固定メッセージ以外は警告へ出ない。
- Given: 子プロセスの失敗、空の回答、タイムアウト、取消。Then: 既存の失敗として返し、警告を理由に成功へ変えない。子と一時ファイルの終了処理を保つ。
- Given: 既存フィールドだけを読むJSON・serdeの利用側。Then: 本文・status・比較の型と意味を変えず、新しい任意情報として読み進められる。

結果に未知の項目があるだけで拒否する厳密な利用側は、追加フィールドを許容する変更が必要です。
既存のフィールドは削除・改名せず、成功とエラーの区別も変えません。

## 評価範囲

合成の接続先で、実プロセス・CLI・MCPの返却まで確認します。
モデルの再生成、全体のSkill設定、個人の指示ファイル、ガイドのPowerPointは変更しません。
テストの入力には、架空の診断と文章を使います。実際の認証値や個人のファイル内容は使いません。

Unslopの改稿方針は配布Skillから実行時のプロンプトへ埋め込まれているため、Skillの自動選択とは別の経路です。
警告がないことも、自動選択や全指示の読込みを保証しません。
