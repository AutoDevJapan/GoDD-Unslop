# 初期の評価

初版の17テストでは、候補の検出、自然な対照文、引用・コード・URLの保護、数量変更の確認、UTF-8位置、入力上限、CLIとMCPの実通信を確認する構成でした。  
機械が意味の等価性を保証するテストではありません。

pilot-features.jsonには、初期評価で取得した公開ページ4件、初期評価で生成したAI例文4件、オーナーの短い指摘4件の数値を保存し、特徴を取り出す処理の確認に使いました。  
作者の制作方法が分からない公開ページはunknownとし、人間の文章という正解にしません。

群はテーマ、用途、長さが異なり、件数も少ないため、分類の精度や作者の確率、推敲の効果を示すデータではありません。  
人間らしさを判定するために、特定の平均文長へ文章を機械的に近づけることもしません。

数量・条件・否定・推量・責任の主語は、同じ語が残っていても意味が変わるため、比較ツールは変更した範囲と確認候補を示すにとどめ、最後に利用者が原文と文脈を照合します。

検出はCommonMarkのText要素を、引用とURLの保護範囲でさらに分けて行うため、強調やコードを挟んで分かれた文について、文全体の長さや名詞の連結を検出できない場合があります。  
`、`以外の読点は初期評価のcomma_countには含めません。

## 測定時点と現在の原則

pilot-features.jsonは初期評価時の測定記録であり、現在の実装による再測定値ではありません。  
現在の文長は句点・疑問符・感嘆符と段落などのブロック境界で区切り、段落内の改行だけでは区切りません。  
文数や平均文長は区切り方に依存するため、初期の値と現在の出力を同じ条件の測定として比較しないでください。  
原文が残っていないデータは新しい区切り方で再計算せず、元の測定値を保持します。

意味のつながる語句・節・文はひとまとまりに保ち、文の境界で必要に応じて改行し、空行で話題や意味の距離を表します。  
短さや文字数だけで機械的に分断せず、敬語の有無とは分けて読みやすさを評価します。
