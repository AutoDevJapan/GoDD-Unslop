# 日本語を最初の下書きから自然に書く

このSkillを読み込んだAI自身が、最初の下書きから本文を書く。このSkillのために追加のモデル呼び出しは行わず、別のAIや `godd-unslop rewrite` を通常の手順として呼び出さない。rewriteから呼び出された場合も再実行しない。モデルの重みを変更する仕組みではなく、日本語の品質を常に保証するものでもない。

## 書く前に

依頼の目的、読者、伝える結論、元資料で確認できる事実を押さえる。数値・単位・固有名詞・主語と責任主体・否定・条件・推測の強さ・期限・約束を保持する。曖昧な事実を自然さのために補わない。敬語を増やすことやくだけた語尾に変えることを品質の尺度にしない。引用、コード、URL、Markdownの構造は壊さない。

## 下書きを組み立てる

- 読者が知りたい結論から具体的に書く。抽象語や名詞を積むより、誰が何をするかを動詞で示す。
- 理由と判断、条件と結果、行動と目的など、意味がつながる節を一文の中で自然につなぐ。一文に異なる話題を詰め込まない。
- 褒め言葉、不要な前置き、同じ結論の言い換え、架空の対立を加えない。専門語が読者の判断に必要なら具体的な説明とともに残す。

例（いずれも架空）:

修正前: 「確認を実施しました。結果は問題なしです。公開作業への移行が可能な状態です。」
修正後: 「確認で問題が見つからなかったため、公開作業へ進めます。」
理由と次の行動をつなぐ。実際に公開したとは書かない。

修正前: 「3回失敗した場合のみ停止します。成功時は停止しません。」
修正後: 「3回失敗した場合だけ停止し、成功時は停止しません。」
条件と否定をそのまま保つ。「3回」を「数回」に丸めない。

## 改行と空行

改行と空行は役割が違う。意味のまとまりと、まとまり同士の距離を、この二つで表す。

- 改行は、同じ話題の中で意味のまとまり（節や文）を読み分ける区切りとして使う。新しい要点、条件、補足、次の動作に移るところで入れてよい。
- 句点があるだけで必ず改行したり、必ず一文につないだりしない。前の文の理由・条件・結果として続けて読ませたい内容は一文につなぎ、独立した要点は文や行を分ける。
- 空行は、話題や段落が変わる距離を表す。同じ話題の中の行ごとに空行を入れず、別の話題の間には空行を残す。
- 原文に意図した改行や空行があれば尊重し、必要もなく一つにまとめたり詰めたりしない。原文に空行がなければ、必要がない限り空行を足さない。
- 箇条書き、手順、宛名、署名など、行の構造そのものに意味があるものは保つ。
- 文の長さ、段落数、文ごとの改行数を固定しない。短くまとめることを目的にしない。

例（いずれも架空）:

同じ話題の中で、つなぐ内容と分ける内容を区別する。

修正前:
```text
保存先を変更しました。次回から新しいフォルダーへ保存します。既存のファイルは移動していません。
```
修正後:
```text
保存先を変更したので、次回から新しいフォルダーへ保存します。
既存のファイルは移動していません。
```
変更と次回の動作はつなぎ、独立した補足は改行で分ける。

話題の切れ目の空行と、同じ話題の中の改行を両方残す。

修正前:
```text
確認は終わりました。
結果に問題はありません。

次の案件を説明します。
担当者は火曜日までに資料を用意します。
```
修正後:
```text
確認は終わり、結果に問題はありません。

次の案件を説明します。
担当者は火曜日までに資料を用意します。
```
空行は話題の距離、行の区切りは同じ話題の中の区切りとして残す。

原文で分かれている独立した案内を一つにまとめない。

修正前:
```text
料金は変わりません。

解約は設定画面から行えます。

不明な点は問い合わせ窓口へ連絡してください。
```
修正後:
```text
料金は変わりません。

解約は設定画面から行えます。

不明な点があれば、問い合わせ窓口へ連絡してください。
```
三つの案内は話題が別なので段落を保つ。語句を整えても、段落数を減らさない。

## 出力前に

原文や資料と照合し、情報を落としていないか、条件や主体が移っていないかを読む。言い換えただけで意味の一致を保証しない。本文を求められたら完成した本文を返し、推敲の説明だけで終えない。

利用可能なら `godd-unslop analyze` で表現候補、`compare` で原文と改稿を照合できる。候補は採否を判断するための補助であり、全件の機械的修正はしない。数字や否定語の件数が同じでも意味が同じとは限らない。

明示された修正例だけを `style-learn` へ渡せる。返るJSON設定を利用者が明示的に保存し、`style-review` へ渡す。自動で会話履歴や私的な文例を集めたり、公開したりしない。学習は前後の文字列との一致に基づき、意味解析や口調の推定ではない。設定内の競合は勝手に一方を選ばない。ツールがない環境でも、このSkillの方針で本文を書き、使っていないツールを実行済みと言わない。
