# GoDD Unslop

GoDD Unslopには、日本語の下書きに使うSkillと、書いた文章を見直すツールがあります。

AIに報告や説明を頼むときは、Skillで自然な文と段落にまとめるよう指示できます。\
書いた後は、ツールの指摘を手がかりに、結論や「誰が何をするのか」が伝わるかを確かめます。

たとえば「既定の保存先です。」だけでは、どこに保存されるか分からないことがあります。GoDD Unslopは「既定」を見つけ、保存先を具体的に書くよう促します。\
指摘された言葉をすべて直す必要はなく、前後の説明で保存先が分かるなら、そのままで構いません。

[図解ガイド（PowerPoint）](docs/user-guide.pptx)では、AIでの改稿、Skillの導入、相手別の設定、改行の好みを、操作の流れと例で説明しています。\
スライドを作る場合は、[ADJ共通スライドテンプレート](docs/templates/)も再利用できます。

実際に試すときは、[文章版のユーザーガイド](docs/user-guide.md)と[サンプルファイル](docs/guide-examples/)を使ってください。

## まず使ってみる

Rust 1.95以降とGitを用意し、次のコマンドを順番に実行します。

```sh
git clone https://github.com/AutoDevJapan/GoDD-Unslop.git
cd GoDD-Unslop
cargo install --path . --locked
godd-unslop analyze docs/guide-examples/article.txt
```

最後のコマンドでサンプルの文章を調べると、結果がJSON形式で表示されます。`explanation`は指摘の理由、`review_action`は確認する内容です。

自分の文章を調べる場合は、UTF-8で保存したテキストファイルを指定してください。

```sh
godd-unslop analyze article.txt
```

結果の読み方や、コマンドが見つからない場合の対処は[ユーザーガイド](docs/user-guide.md)にまとめています。

## AIに最初から文章を書いてもらう

普段使うAIにSkillを読み込ませると、下書きから理由と結論のつながりや話題ごとの段落を意識して書くよう指示できます。
文章を書くAI自身が方針を使うため、Skillから別のAIを呼ぶ必要はありません。モデルの再学習や日本語の品質保証を行うものではありません。

使うアプリのSkillルートフォルダーを`install-skill`の引数に指定すると、その下に`godd-unslop/SKILL.md`が保存されます。保存先と使い始め方は[導入手順](docs/user-guide.md#aiに文章を書いてもらうためのskillを入れる)で確認できます。

導入しただけでは毎回自動で選ばれるとは限らないので、まずは依頼の先頭でSkillを指定し、読者と必要な事実を伝えてください。\
Codex CLIでは`$godd-unslop`、Claude Codeでは`/godd-unslop`を付けます。どちらも同じ配布Skill本文を使います。

たとえば、`codex`で起動した対話画面の入力欄へ、次の文章を貼り付けて送信します。Claude Codeの対話画面では、先頭行を`/godd-unslop`に替えます。

```text
$godd-unslop
同僚へ送る社内チャットを書いてください。
資料の保存先を「チーム共有」に変更し、既存ファイルは元の場所に残しています。
```

## 手元の文章をAIで書き直す

CLIから改稿を受け取るには`rewrite`を使います。ChatGPTサブスクでログインしたCodex CLIが必要で、APIキーは使いません。実行ファイルの指定や認証の確認は[AI改稿の手順](docs/user-guide.md#codex-cliで文章を書き直す)を参照してください。

次の内容をUTF-8の`rewrite-request.json`に保存します。

```json
{"text":"確認を実施しました。結果は問題なしです。公開作業への移行が可能な状態です。"}
```

保存したファイルを次のコマンドに渡します。

```sh
godd-unslop rewrite rewrite-request.json
```

改稿は`rewritten_text`、原文との比較は`comparison`で確認できます。\
`meaning_warnings`と`layout_warnings`には、確認すべき点が表示されます。

`runtime_warnings`が空でない場合は、Codexが一部のSkillや指示を読み込めなかった可能性があります。改稿が成功していても、必要な方針が反映されているか確認してください。

改稿では、同じ話題の中の意味の区切りに改行を使い、話題の切れ目には空行で間を取ります。原文の段落は必要以上に詰めないようにしています。

元ファイルは書き換えません。改稿を採用する前に、条件や責任主体が変わっていないか原文と読み比べてください。

## 相手に合わせて伝え方を変える

部下への柔らかい依頼、同僚との普段のやり取り、上司への報告では、同じ内容でも言い方が変わります。
相手との親しさに加えて、敬語の程度、柔らかさ、率直さ、絵文字の使い方を指定できます。公式文書では絵文字を使いません。

相手ごとの設定は端末内のDBへ保存し、改稿するときに必要な相手を選べます。保存・訂正・削除や、今回だけ文体を変える手順は[相手と場面に合わせるガイド](docs/recipient-context.md)にまとめています。

背景が足りないときは、Skillを使うAIが参照を許可された資料を調べ、重要な不明点だけを質問します。\
CLIでは`context`で背景を渡します。必要な情報がまだないと指定した場合は、改稿せずに質問を返します。

## 書き直すときに使う

文章をどう見直せばよいか迷ったら、`plan`で確認の手順を表示できます。

```sh
godd-unslop plan article.txt
```

`plan`は本文を書き換えず、見直しの手順を返します。表示された手順を参考に、自分で直すか、文章を書くAIに修正を依頼してください。

書き直した後は、`compare`で原文と比べられます。

```sh
godd-unslop compare article.txt revised.txt
```

たとえば「3回」を「5回」に変えると、数量が変わったことを知らせます。\
「担当者が承認する」を「承認者が担当する」に変えた場合のように、使った言葉が同じでも意味が変わることはあります。

比較結果だけで修正の良し悪しを決めず、伝えたい内容が変わっていないか、原文と読み比べてください。

## 改行や空行の入れ方を覚えさせる

改行や空行の入れ方で、文章の読みやすさは変わります。意味のつながる内容をまとめ、話題が変わるところでは間を空けるといった書き方を修正例で教えられます。

次は、二つの文の間に改行を入れる例です。

修正前:

```text
記録を保存しました。次に確認します。
```

修正後:

```text
記録を保存しました。
次に確認します。
```

この修正を登録すると、同じ語句の並びが出てきたときに、改行を入れる案が返ります。
文章の意味を理解して、どんな文章にも同じように応用できる段階ではありません。

修正例の登録には`style-learn`、登録した内容で文章を確認するには`style-review`を使います。
[設定の保存・再利用の手順](docs/user-guide.md#改行と空行を修正例から学ぶ)に、コピーして使える例を載せています。

会話から自動で覚えたり、設定を自動保存したりはしないため、次回も使いたい設定はファイルに保存してください。

保存した設定には例文の言葉が残るので、個人の文章や仕事の内容を含むものは公開しないでください。

## AIツールや自作のアプリから使う

コマンドのほか、MCPに対応したAIツールやRustで作ったアプリからも呼び出せます。

分析・比較と修正例の照合は生成モデルを呼び出しません。`rewrite`はCodex CLIを通じて原文をChatGPTへ送り、改稿を受け取ります。

MCPを使う場合は、対応するアプリに`godd-unslop serve`を登録します。Codex CLIとClaude Codeそれぞれの登録・接続確認と、生成モデルを呼ばない`unslop_compare`を同じ入力で試す手順は、[ユーザーガイドのMCP設定](docs/user-guide.md#mcpクライアントから使う)を参照してください。

MCPを使うアプリのログインと、`unslop_rewrite`が使うCodexのChatGPTログインは別です。

Rustから使う場合は、`analyze`、`plan`、`compare`、`features`、`style::learn`、`style::review`、`rewrite::run`を利用できます。
MCPが不要なら、依存関係の指定に`default-features = false`を付けられます。

## 詳しい仕様を調べる

文章の長さや漢字の割合を調べるには、`features`を使います。

```sh
godd-unslop features article.txt
```

文章の良し悪しは長さや漢字の割合だけでは決まらないため、これらの数値は傾向を確認するときの参考にしてください。

入力できる文章の大きさ、結果に表示される位置の数え方、Markdownの扱い、終了コードなどは[ユーザーガイド](docs/user-guide.md)にまとめています。

特徴の計算方法と初期の測定データについては、[評価の説明](docs/evaluation.md)と[データの収集方針](docs/data-policy.md)を参照してください。
