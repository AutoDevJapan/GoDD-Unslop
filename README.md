# GoDD Unslop

GoDD Unslopは、文章の分かりにくいところを見つけ、書き直すときに確認したい点を教えるツールです。  
報告や説明を書くときに、「結局、何が言いたいのか」「誰が何をするのか」が伝わっているかを見直すために作っています。

たとえば「既定の保存先です。」とだけ書いても、読み手には保存先が分からないかもしれません。  
GoDD Unslopは「既定」という言葉を見つけ、保存先を具体的に説明するよう促します。

指摘された言葉を、すべて直す必要はありません。  
前後の説明を読めば保存先が分かるなら、そのままで構いません。

[図解ガイド（PowerPoint）](docs/user-guide.pptx)では、操作の流れを図や実行例で説明しています。  
実際に試すときは、[文章版のユーザーガイド](docs/user-guide.md)と[サンプルファイル](docs/guide-examples/)を使ってください。

## まず使ってみる

Rust 1.95以降とGitを用意し、次のコマンドを順番に実行します。

```sh
git clone https://github.com/AutoDevJapan/GoDD-Unslop.git
cd GoDD-Unslop
cargo install --path . --locked
godd-unslop analyze docs/guide-examples/article.txt
```

最後のコマンドで、サンプルの文章を調べます。  
結果の`explanation`に指摘の理由、`review_action`に確認する内容が表示されます。

自分の文章を調べる場合は、UTF-8で保存したテキストファイルを指定してください。

```sh
godd-unslop analyze article.txt
```

結果はJSON形式で表示されます。  
読み方や、コマンドが見つからない場合の対処は[ユーザーガイド](docs/user-guide.md)にまとめています。

## 書き直すときに使う

文章をどう見直せばよいか迷ったら、`plan`で確認の手順を表示できます。

```sh
godd-unslop plan article.txt
```

GoDD Unslopが文章を書き換えるわけではありません。  
表示された手順を参考に、自分で直すか、文章を作成するAIへ修正を依頼してください。

書き直した後は、`compare`で原文と比べられます。

```sh
godd-unslop compare article.txt revised.txt
```

たとえば「3回」を「5回」に変えると、数量が変わったことを知らせます。  
ただし、「担当者が承認する」を「承認者が担当する」に変えた場合のように、使った言葉が同じでも意味が変わることはあります。

比較結果だけで修正の良し悪しを決めず、伝えたい内容が変わっていないか、原文と読み比べてください。

## 改行や空行の入れ方を覚えさせる

改行位置や空行の入れ方は、文章の読みやすさに関わります。  
意味のつながる内容はまとめ、話題が変わるところでは間を空ける、といった書き方を修正例で教えられます。

たとえば、次のように改行を入れたい場合です。

修正前:

```text
記録を保存しました。次に確認します。
```

修正後:

```text
記録を保存しました。
次に確認します。
```

この修正を登録しておくと、同じ語句の並びが出てきたときに、改行を入れる案を返します。  
文章の意味を理解して、どんな文章にも同じように応用できる段階ではありません。

修正例の登録には`style-learn`、登録した内容で文章を確認するには`style-review`を使います。  
[設定の保存・再利用の手順](docs/user-guide.md#改行と空行を修正例から学ぶ)に、コピーして使える例を載せています。

会話から自動で覚えたり、設定を自動保存したりはしないため、次回も使いたい設定はファイルに保存してください。  
保存した設定には例文の言葉が残るので、個人の文章や仕事の内容を含むものは公開しないでください。

## AIツールや自作のアプリから使う

コマンドで実行するほか、MCPに対応したAIツールや、Rustで作ったアプリからも呼び出せます。  
GoDD Unslop自体は生成モデルを呼び出さず、文章を外部へ送りません。

MCPを使う場合は、対応するアプリに`godd-unslop serve`を登録します。  
設定例と利用できる機能は[ユーザーガイドのMCP設定](docs/user-guide.md#mcpクライアントから使う)を参照してください。

Rustから使う場合は、`analyze`、`plan`、`compare`、`features`、`style::learn`、`style::review`を利用できます。  
MCPが不要なら、依存関係の指定に`default-features = false`を付けられます。

## 詳しい仕様を調べる

文章の長さや漢字の割合を調べるには、`features`を使います。

```sh
godd-unslop features article.txt
```

文章の長さや漢字の割合だけで、良い文章かどうかは決まりません。  
これらの数値は、文章の傾向を確認するときの参考にしてください。

入力できる文章の大きさ、結果に表示される位置の数え方、Markdownの扱い、終了コードなどは[ユーザーガイド](docs/user-guide.md)にまとめています。  
特徴の計算方法と初期の測定データについては、[評価の説明](docs/evaluation.md)と[データの収集方針](docs/data-policy.md)を参照してください。

## 開発に参加する

```sh
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --all-targets --locked
cargo test --no-default-features --locked
```

文章の指摘だけでなく、引用やコードを誤って扱わないこと、原文と比較できること、CLIとMCPから利用できることをテストしています。  
GitHub ActionsではUbuntuとWindowsで確認します。
